The default mnemonic is a public test vector (Hardhat / Anvil). Anyone can derive its keys: never send real funds to it, and never type a mnemonic that protects real money into a web page.

Reproducing it with a real wallet

The assignment suggests comparing with MetaMask, Rabby, Exodus or Rainbow. A safe way: in a fresh, empty browser profile, choose “import wallet” and paste the test mnemonic above. The first account must show 0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266 and the second 0x70997970C51812dc3A010C7d01b50e0d17dc79C8: the same addresses this page computes for indices 0 and 1 (path m/44'/60'/0'/0/i). Changing the passphrase here changes the whole chain of addresses, which is what happens when a hardware wallet uses a passphrase. The same words in a wallet with a different path (for example Ledger Live's m/44'/60'/i'/0/0) produce different accounts: the practical reason BIP-44 exists.

Statistical check of the checksum layer

EIP-55 hides a checksum in the capitalisation: hash the lower-case hex address with Keccak-256 and capitalise every letter whose matching hash digit is ≥ 8. An address with L letters therefore carries L checksum bits (about 15 on average, 40 digits × 6/16). The experiment creates random addresses, changes one hex digit anywhere (keeping the original capitalisation of the others) and counts how often a validator notices.

The six pieces, one paragraph each

BIP-39 · mnemonic and seed

A SHA-256 checksum (ENT/32 bits) is appended to the 128–256 bits of entropy and the whole is cut into 11-bit groups; each group indexes the list of 2048 words. 12 words = 128 + 4 bits, 24 words = 256 + 8 bits. The seed is PBKDF2-HMAC-SHA512(mnemonic, "mnemonic" + passphrase, 2048 iterations), 64 bytes. The words are an encoding a person can write down; the PBKDF2 step is the key derivation and adds work for anyone trying to brute-force it.

BIP-32 · hierarchical deterministic keys

The master key and chain code are the two halves of HMAC-SHA512("Bitcoin seed", seed). A child is derived with HMAC-SHA512(chaincode, data ‖ index); the left half is added to the parent key modulo n. Indices ≥ 2³¹ are “hardened”: the parent's private key enters the HMAC, so a child key with its chain code does not allow going back up to the parent. A single backup covers an unlimited tree of keys.

BIP-44 · derivation paths

A convention on top of BIP-32: m / purpose' / coin_type' / account' / change / address_index. Ethereum uses purpose 44 and coin type 60, Bitcoin coin type 0. It adds no cryptography: it makes two wallets that follow it find the same accounts from the same words.

secp256k1 · the link between the keys

The curve y² = x³ + 7 over a 256-bit prime field. The public key is Q = kG; signatures (ECDSA) prove knowledge of k without revealing it. Ethereum signatures are recoverable: from the signature itself one computes the public key and hence the sender's address.

Keccak-256 · hashing

The 64 raw bytes x ‖ y (without the 0x04 prefix) are hashed and the last 20 bytes become the address. The hash shortens the identifier and puts a second, hash-based barrier in front of the public key until the first signature reveals it.

EIP-55 · checksum in the capitals

Backward compatible: the address bytes do not change, only the capitalisation encodes about 15 checksum bits. Software that ignores case still works; software that checks it catches almost every typo (simulation above).

Why one algorithm is not enough

Each primitive is built for a different security goal, and no single algorithm meets them all.

GoalPrimitiveWhy another one would not do
Back up a single secret and recover everything from itBIP-39 → BIP-32 → BIP-44A hash or a curve gives no portable backup format, no tree of accounts, and no agreement between wallets on which path to use. These standards are about key management, not hardness assumptions.
Publish something that says nothing about k yet lets others verify signaturessecp256k1 (ECDSA)A hash cannot verify a signature without the secret; only an asymmetric structure lets a public value check a private operation. That same structure (a homomorphism) is exactly what a hash must not have.
Short, uniform, fixed-size identifierKeccak-256A curve point is 64 bytes with algebraic structure; the address needs 20 with no structure at all, and a hash provides that for any input.
Catch typos before sending moneyEIP-55Only redundancy is needed, not security; it is cheap and stays compatible with lower-case addresses. A cryptographic signature here would add size while giving nothing more than a checksum.
