Part 1 · public-key schemeEncrypting a message with the secp256k1 toy scheme

The scheme from the previous homework turns the elliptic-curve key pair into an encryption method. It is a stripped-down version of ECIES, also called hashed ElGamal: the public key is used to agree on a one-time secret, and that secret drives a simple stream cipher. The private key d is limited to a small number of bits so that attacks can be run in a browser; everything else uses the real secp256k1 curve (y² = x³ + 7 over a 256-bit prime field, generator G).

Part 2 · classical cipherThe Caesar cipher on the same message

Each letter is moved k places along the alphabet, wrapping around after Z. Encryption is c = (m + k) mod 26 and decryption is m = (c − k) mod 26. The key k is shared secretly between sender and receiver, so this is a symmetric cipher. Spaces and punctuation are left alone.

Take-away. Caesar changes the names of the letters but not their statistics, so the ciphertext still carries the fingerprint of the language. The ECC scheme produces key stream from a hash, so the ciphertext looks uniformly random whatever the plaintext is, and statistics of the ciphertext give nothing. Its weakness is of a different kind: if d lives in a small set, the attacker can test the keys directly.

Part 4 · cryptanalysisRecovering a Caesar key from letter statistics

A shift does not change how often each letter occurs, it only moves the counts to different letters. The attacker needs only the language of the message and a large sample of that language. For each of the 26 keys, undo the shift and ask how English-like the result is. The key with the best score is the answer. This is a ciphertext-only attack: no plaintext is known.

The reference corpus

The model is built from a large text of known language: the King James Bible (public domain), about 3.2 million letters. It contains single-letter, two-letter and three-letter statistics. The attack is then tested on a different kind of text, modern technical English (Python documentation prose and software licence text), so the test measures how well the statistics carry over to new text.

Model of EnglishEntropy per letter (bits)Redundancy D (bits)Unicity distance (letters)

Redundancy is D = log₂26 − H, the information each letter fails to carry. Shannon's unicity distance U = H(key) / D = log₂26 / D estimates how many ciphertext letters are needed before only one key is plausible. With the richer models the bound falls to a few letters; real attacks need more, because the models are imperfect and each decision has a statistical error rate. Entropies are estimated from this corpus (single, bigram and trigram conditional entropy).

The algorithm

// chi-square attack on the Caesar cipher
// freq[j]: relative frequency of letter j in the corpus
function recoverKey(cipher) {
  const n = count of letters in cipher;
  const obs = histogram of the 26 letters of cipher;
  let best = null;
  for (let k = 0; k < 26; k++) {          // try every key
    let chi2 = 0;
    for (let j = 0; j < 26; j++) {        // plain letter j appears
      const o = obs[(j + k) % 26];         // as cipher letter j + k
      const e = n * freq[j];
      chi2 += (o - e) ** 2 / e;
    }
    if (best === null || chi2 < best.chi2) best = { k, chi2 };
  }
  return best.k;                           // smallest distance wins
}

Effectiveness and limitations

What the results show

Each rate is an estimate from a finite number of trials, so values carry a sampling error of about ±2 percentage points; small dips between neighbouring lengths are noise.

Limitations

Short messages give thin evidence. The default message has 11 letters. Chi-square, bigram and trigram scores and the word check find its key, but the margins are small: the unigram log-likelihood prefers k = 22 over the true k = 7 by a hair, and the “most frequent letter is E” shortcut picks the wrong key. Random 11-letter passages fail more often (chart above). The data, not the algorithm, is the limit.

The language must be known. With the Italian sample (about 330 letters) the four statistical methods still find the key with the English model, because the shape of the letter distribution is similar, while the word check (English words only) and the E shortcut fail. With a shorter text, or a language whose letters are used very differently, the English model would degrade; the right choice is a corpus of the language of the message.

Mismatched corpora cost accuracy. The model here was trained on archaic prose and tested on technical prose. In a separate check run outside this page, a model trained on half of the modern text raised the chi-square success rate at 20 letters from 84% to 96%, and the trigram rate at 5 letters from 73% to 86%. Short texts benefit most from a reference text in the same style as the message.

Unusual texts break the assumption. Numbers, code listings, or text written without a common letter (a lipogram) do not follow the reference frequencies.

Part 5 · cryptanalysisAttacking the toy ECC scheme through its key range

The ECC scheme does not leak statistics, so the Caesar approach has nothing to work with. But the attacker knows Bob's public key Q = d·G, and a candidate d can be checked by computing d·G and comparing it with Q. If d is known to lie in a small range, that check can be repeated until it succeeds. Once d is known, the attacker decrypts exactly like Bob.

Brute force

Compute 1·G, 2·G, 3·G, … by adding G each time and compare with Q. At most 2b steps and no memory. Each step is one point addition.

Baby-step giant-step (Shanks)

Write d = i·m + j with m = ⌈√(2b)⌉. Store the points j·G for j < m (baby steps). Then compute Q − i·(m·G) for i = 0, 1, 2, … (giant steps) until the result is in the table. About 2·2b/2 operations and 2b/2 table entries: the square root of brute force. The table does not depend on Q, so it serves every victim with the same key range.

Run the attack

The attacker never uses the ciphertext to find the key, so the result does not depend on the message: a one-letter message and a long text fall equally fast. In the second setting, Alice also drew r from the small range, so r can be recovered from the public value R, and the message opens with public information only. Bob's private key is not needed.

Why this does not work against a proper key. With d spread over about 2256 values, brute force needs around 2255 steps, and even the best generic algorithms (baby-step giant-step, Pollard's rho) need about 2128 group operations. The table of baby-step giant-step would need 2128 entries, which no storage can hold; Pollard's rho avoids the memory but not the time. At 1018 operations per second, 2128 operations still take about 1013 years. There is also no shortcut from the structure of the curve: secp256k1 has prime order and no known weakness, so the elliptic-curve discrete logarithm has no sub-exponential algorithm, in contrast to factoring or the discrete logarithm in finite fields. A large quantum computer running Shor's algorithm is the known exception, and the reason why post-quantum schemes are being standardised.

Conclusions

Both ciphers fall to an attacker who can try all keys, and both attacks are cheap here for the same reason: the key space is small. They differ in what makes the test of a candidate possible. Against Caesar the only check is statistical, so the success rate depends on how much ciphertext there is. Against the toy ECC scheme the public key gives an exact check, so success does not depend on the message at all, and only the key range sets the cost: 2b steps, or 2b/2 with baby-step giant-step. With a full 256-bit key the same algorithms stay out of reach, and the remaining risks are the design weaknesses listed above, which a real scheme (ECIES with authenticated encryption, or a modern hybrid encryption standard) closes with a MAC or an AEAD cipher, fresh randomness, and context binding in the key derivation.

Data and method

Reference corpus: text of the King James Bible (1769 edition, public domain), taken from the kjv npm package: 3,222,408 letters, from which the single-letter, bigram and trigram statistics were computed (add-0.5 smoothing for the n-gram tables, quantised to 8 bits per entry in this page). Test text: about 106,000 characters of modern technical English made of prose paragraphs from the Python language reference documentation and the text of the GNU GPL v3 and Apache 2.0 licences. The test text was never used for training. The word list for the exhaustive search is 273 very common English words. Elliptic-curve arithmetic is exact 256-bit integer arithmetic (BigInt) on secp256k1 using the code from the previous homework, checked against known values (for example 2·G and the address of private key 1). Simulations use seeded generators, so results are reproducible; key and nonce generation in the cipher demos uses the browser's secure random generator.
