Hands-on partPrivate key → public key on a toy curve

Scalar multiplication $Q = kG$ is easy to compute and, it is believed, hard to invert: this is the property a wallet relies on. The key $k$ stays secret, $Q$ can be published. The goal is to see the mechanism on a curve small enough to follow by hand, not to build a real cryptosystem.

Parameters

curve E: y² = x³ + 7 (mod 17) base G = (1, 5) check 5² = 25 ≡ 8, 1³ + 7 = 8 ✓ private k = 6 public Q = kG = 6G

Counting the solutions of the equation gives 17 affine points; with the point at infinity $O$ the group has 18 elements. Adding $G$ to itself returns to $O$ after 9 steps: $G$ generates a subgroup of order 9 and every $k$ behaves like $k \bmod 9$. This toy offers no security at all: the group is tiny and, since $17 \equiv 2 \pmod 3$, the curve is supersingular, which makes discrete logarithms even easier.

Point addition in 4 lines

P ≠ Q: λ = (y₂ − y₁)(x₂ − x₁)⁻¹ P = Q: λ = 3x₁² (2y₁)⁻¹ x₃ = λ² − x₁ − x₂ y₃ = λ(x₁ − x₃) − y₁ (all mod p) P + (−P) = O, −(x, y) = (x, −y)

Geometrically: draw the line through $P$ and $Q$ (the tangent if $P = Q$), take its third intersection with the curve and reflect it across the x axis. Modulo 17 the “line” is the set of residues $y \equiv \lambda(x - x_1) + y_1$, drawn as dots in the plot below.

Statistical explorationWhat does kG look like statistically?

      
The assignment lists several properties to look at: distribution of the coordinates, frequency of values, bit balance, uniformity, input/output correlation, avalanche. Two experiments follow. First an exhaustive one on the toy curve, where all points can be listed. Then a sampled one on the real secp256k1 curve, with exact 256-bit arithmetic (BigInt), where the numbers actually mean something.


      
2.1 Toy curve, exhaustive

      

        

          

        

          
          
          
        

        

        
Reading the toy results. Choose the base point (6, 6), which generates all 18 elements, to see the full picture. Over a whole period the map k ↦ kG is a bijection onto the subgroup, so every point appears exactly once. The (x, y) pairs are uniform by construction, not because the map “mixes” anything. The two coordinates behave very differently: on this curve every y from 0 to 16 appears once (the cube map is a bijection mod 17, so y determines x), while only 9 of the 17 possible x values appear, and x(kG) = x(−kG), so values come in mirror pairs. The scatter is a repeated, symmetric pattern, the opposite of an avalanche. With 18 elements no statistic has cryptographic meaning: the toy only shows the structure.

      


      
2.2 Real curve: secp256k1, sampled

      
The same experiment with the curve used by Bitcoin and Ethereum: $p = 2^{256} - 2^{32} - 977$, group order $n \approx 2^{256}$, $G$ the standard generator. For each sampled private key $k$ the page computes $Q = kG$ with exact arithmetic and analyses the 256 bits of the x coordinate. Keys come from a seeded PRNG, so every run is reproducible. The “sequential” mode uses $k = 1, 2, 3, \dots$, the hardest case for a function that must hide its input.

Collision resistancePractically moot: for 0 < k < n the map is injective, so two keys never share a pointNot applicableRequired, and limited by the 2¹²⁸ birthday bound for 256-bit hashes

          
Arbitrary-length inputThe input is a single scalar below nNot applicableRequired (Merkle–Damgård, sponge)

          
Algebraic structure(k₁ + k₂)G = k₁G + k₂G: the map is a group homomorphism. Statistical tests do not see itUseful: enables signatures, key exchange, MuSig, derived keysFatal: a hash with this structure would be broken

        

      
Conclusion. kG passes the statistical checks usually run on hashes, but these only show that there is no simple relation between k and Q. The security argument is a different one: no known algorithm inverts the map in fewer than about 2¹²⁸ steps, and the structure that makes it useful (it is a homomorphism) would disqualify it as a hash. Both appear in the Ethereum pipeline, each with its own job: kG for the link between the keys, Keccak-256 to compress the public key into an address.
